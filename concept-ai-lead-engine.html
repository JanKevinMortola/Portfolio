Architecture

One funnel, multiple control points.

The system separates capture, identity resolution, qualification, CRM state and operational handoff so each layer can be monitored independently.

Identity control

Deduplication before CRM creation

Normalize email, phone and source data; search existing contacts; merge or route ambiguous matches before creating duplicates.

AI assist

Qualification with guardrails

Use AI to extract intent or summarize free-text context, while deterministic rules control hard eligibility and routing thresholds.

SLA

Response-time monitoring

Track high-priority leads that have not received the expected action and escalate before they quietly age in the pipeline.

Automation mix

Use each platform deliberately

GHL owns CRM state; n8n handles complex orchestration; Make/Zapier cover fast SaaS connections where maintainability is better.

Handoff

Won deal → operations

When an opportunity changes state, create the correct downstream project, onboarding task, folder or fulfillment record.

Recovery

Exception queue

Failed enrichments, ambiguous duplicates, missing fields and API errors enter a visible review queue instead of disappearing.

Why this architecture

Revenue automation needs clean identity and explicit ownership.

A fast follow-up system is only useful if it knows who the lead is, who owns it, what state it is in and what should happen when the normal path fails.
